# План: SSD-хранилище для торрентов и медиатеки (USB 3.0)

> Исходные данные: SSD с разделом NTFS и старой Windows внутри; тариф 900 Мбит/с;
> сценарий — качать торренты, смотреть фильмы с устройств по Wi-Fi, в перспективе
> своё приложение-медиатека (позиции просмотра, продолжение серии).

## 1. Пропустит ли цепочка гигабит? — Да, с запасом

| Звено | Пропускная способность | Оценка |
|---|---|---|
| Тариф | 900 Мбит/с ≈ **112 МБ/с** | база |
| SATA SSD | 400–500 МБ/с запись | запас ×4 |
| USB 3.0 на KN-1811 | сотни МБ/с (зависит от чипа бокса) | запас ×2–3 |
| SMB на Keenetic | ~90–110 МБ/с (по опыту сообщества, сверить iperf'ом) | ≈ канал, впритык но достаточно |
| Wi-Fi 6 5 ГГц клиентам | 600–1200 Мбит/с рядом с роутером | 4K-стрим (50–120 Мбит/с) — легко |

Узкие места на практике: CPU роутера если торрент-трафик завернётся в XKeen
(настроить политику «Transmission — напрямую», статья 50384), и драйвер NTFS
(лечится переходом на ext4, см. ниже).

## 2. Файловая система: NTFS → ext4 (обязательно)

- Официально (ст. 43341): «Если вы планируете записывать объемные данные,
  рекомендуется перейти на файловую систему EXT4, для которой не требуется
  преаллокация» — NTFS тормозит на записи торрентов (кластер 4K, преаллокация).
- Для ext4 на роутере нужен компонент **«Файловая система Ext»** (есть в нашем плане установки).
- ext4 не читается Windows нативно — не проблема: доступ через SMB/DLNA/WebDAV с роутера.
- Поддержка metadata_csum в KeeneticOS 5.x есть (ограничение было только до NDMS 2.15),
  но форматировать можно так же, как флешку: `-O ^metadata_csum,^64bit` — безопасный вариант.
- 5% места ext4 резервирует под root: для медиатеки отдать — `tune2fs -m 0 /dev/sdX1`.

## 3. Подготовка SSD

1. **Сохранить данные**, если на старом Windows-разделе что-то нужно (иначе — снести всё).
2. DiskGenius (проверенный путь): удалить все разделы → один **Primary EXT4** на весь объём,
   метка `STORAGE` → Save All.
3. Порт: **USB 3.0** (флешка-система остаётся в USB 2.0).
4. После подключения проверить в веб → Приложения → Диски; сверить скорость
   копированием большого файла по SMB (цель ≥ 100 МБ/с).

Каталоги на диске: `downloads/` (каталог закачек Transmission), `movies/`, `series/`,
`apps/` (БД/конфиги под будущее приложение).

## 4. Доступ к медиа с устройств (встроенные средства KeeneticOS)

- **SMB** — ПК, Android-боксы, мапится как сетевой диск.
- **DLNA (Медиатека)** — телевизоры и плееры напрямую.
- **WebDAV/SFTP** — по желанию (мобильные клиенты, VLC).

## 5. Своё приложение-медиатека (будущее)

- v1 (просто): веб-приложение читает каталоги по SMB, позиции просмотра — локально
  (localStorage) или в JSON на диске.
- v2 (серьёзно): после Entware — лёгкий стек на роутере (nginx + python/node + SQLite),
  сканирует `movies/`, `series/`, помнит позиции, отдаёт direct-play ссылки.
  512 МБ RAM хватит только на лёгкий стек — **транскодирование на роутере не потянет**:
  плеер на клиенте должен сам играть форматы (VLC, Infuse, VidHub и т.п.).
- Готовая альтернатива: Jellyfin (метаданные+резюм из коробки) — но на 512 МБ RAM
  под большим вопросом; пробовать после Entware, замеряя потребление памяти.

## 6. TRIM

USB-мосты обычно не передают TRIM; для медиатеки (write-once) некритично.
Если мост поддерживает — изредка `fstrim -v /tmp/mnt/...` из Entware.
