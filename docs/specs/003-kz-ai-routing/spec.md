# 003: AI, платежи и верификация через KZ без fallback

Дата: 2026-10-30. Статус: ВНЕДРЕНО, сетевые проверки пройдены 21:05–21:08 МСК.
Полная оплата/верификация в пользовательском браузере не выполнялась.

## Согласованные требования

- R1: весь текущий `category-ai@domain`, а не только Claude, переводится US → KZ.
- R2: Anthropic/Claude, Stripe/Link, Persona, Yoti и выявленные веб-зависимости — KZ-only.
- R3: при отказе KZ эти соединения не уходят ни в NL, ни в US, ни DIRECT.
- R4: YouTube, Meta и основной whitelist сохраняют NL-маршрут; основной
  `Fallback=[reality-home,DIRECT]` сохраняется по прежнему решению владельца.
- R5: US-VM выключает сам владелец после подтверждения миграции; US удаляется из активного Mihomo.
- R6: секреты только в защищённой рабочей конфигурации/бэкапах, в Git — плейсхолдеры.
- R7: после обсуждения всех портов/DNS владелец выбрал **«Пока только веб-трафик»**.
  Перехват TCP/UDP 80,443 и sniffer сохраняются. UDP/443 (QUIC) отвергается.
  Гарантия относится к распознанным доменам трафика, попавшего в Mihomo в режиме rule.
  Это не системный kill-switch: не покрыты остановка XKeen, другой VPN клиента,
  исключённые устройства/IP, ECH/неопознанный SNI, STUN/иные порты, неизвестные
  банковские 3DS-домены и сторонние MCP/SSO. DNS/fake-IP и Wi-Fi не меняем.
- R8: на вопрос reviewer о совместных CDN/Google владелец выбрал **«Только
  сервисные домены»**: общие Google OAuth/Maps/Fonts и CDN библиотек не переводим.

## Исходное состояние (живой роутер)

Mihomo v1.19.31; AI → US-Fallback → reality-us, резерв reality-home.
AI сейчас содержит ручные DIRECT/Fallback/Fastest и include-all — это нужно убрать.
Список us-pool: 24 правила, загружен 30 октября 11:05 МСК.
Логи соединений не сохраняются (warning, stdout/stderr /dev/null).
Перехват TCP/UDP 80,443 присутствует для IPv4 и IPv6; IPv6 default route не найден.
`xkeen_deny_mac`, `user_exclude`, `geo_exclude` на момент проверки пусты.
Репозиторий имеет незакоммиченные изменения предыдущих работ; они сохраняются.

## Решение

1. Вместо reality-us — reality-kz с VLESS/Reality/vision/chrome из ссылки владельца.
2. AI: `type: select`, **ровно `proxies: [reality-kz]`**, без include-all/use.
   US-Fallback удаляется. Ни health-check, ни cache.db не могут выбрать другую ноду.
3. `kz-pool@classical`, file/text/classical, абсолютный путь
   `/opt/etc/mihomo/kz-pool.list`; новый источник истины `mihomo/kz-pool.list`.
   Старый us-pool в репо сохраняется как исторический файл с пометкой, активных ссылок нет.
4. Приоритет: QUIC REJECT → kz-pool AI → category-ai AI → adlist REJECT →
   остальные прежние правила. Явные платежные/верификационные правила должны
   проходить раньше рекламы (например m.stripe.com — антифрод, не просто реклама).
5. Во всех остальных группах `include-all` заменить явным добавлением
   `reality-home` в имеющийся список proxies (Fastest получает только reality-home).
   Так KZ не попадает в Fastest/YouTube/Meta даже после ручного выбора Fastest.
   Остальные существующие ручные варианты и порядок сохраняются; US удаляется.
6. Полный reload конфигурации через локальный API Mihomo, без удаления iptables.
   Старые соединения с защищёнными доменами/AI/US закрыть по ID через API,
   чтобы они не продолжали работать по прежней цепочке. Не закрывать весь NL-пул.
7. Xray остаётся запасным старым ядром, **не поддерживает этот контракт**;
   переключение на него не является допустимым способом восстановления AI.

Альтернативы: KZ→NL запрещено владельцем; AI select с DIRECT запрещён R3;
глобальный режим KZ нарушает R4; все порты+DNS отложены владельцем;
общие cloudflare.com/amazonaws.com/google.com не добавляем целиком.

## Приёмка (контракт до реализации)

T1 (R1/R3): статический тест состава AI, отсутствия US/Fallback достижимости,
реальное API AI.all ровно [reality-kz], now=reality-kz, mode=rule.
T2 (R2): каждый домен из итоговой матрицы research.md покрыт точным DOMAIN либо суффиксом;
KZ-пул сохраняет все действующие правила US-пула (кроме example.invalid);
чужие `notclaude.ai`, `stripe.com.example.org`, `example.com` не покрыты.
T3 (R2/R7): порядок QUIC→KZ→AI→adlist и MATCH,DIRECT последний; все ссылки
на группы/провайдеры разрешаются. Список без дубликатов и некорректных строк.
T4 (R4): NL proxy и основной Fallback семантически идентичны бэкапу;
YouTube/Meta по выбранным цепочкам ведут на reality-home. KZ не достижим из
любой другой сервисной группы, Fastest тоже только NL. Остальные правила сохранены.
T5 (R5/R6): US отсутствует в активных proxies/groups/rules/rule-providers; шаблон не содержит
рабочих UUID/ключей. Реальный конфиг проходит `mihomo -t`.
T6: все rule-providers загружены, count>0. Файл KZ совпадает с репо.
T7: до переключения изолированный Mihomo на loopback с KZ, mixed-port 17891,
external-controller 127.0.0.1:19091, allow-lan=false, routing-mark=255,
без redir/tproxy, с отдельным каталогом и правилом MATCH,reality-kz
проверяет внешний IP и страну (Cloudflare trace + независимый IP-сервис).
Изолированный процесс не меняет перехват/маршруты; после проверки остановить.
Ссылка владельца получена: type=tcp, security=reality, flow=xtls-rprx-vision,
fp=chrome; проверить при заполнении кандидата, spx не используется Mihomo.
T8: после reload живые запросы с LAN к claude.ai, api.anthropic.com, chatgpt.com,
js.stripe.com, checkout.stripe.com, checkout.link.com, inquiry.withpersona.com,
www.yoti.com, js.hcaptcha.com: цепочка AI→reality-kz. 401/403/404 сайта не равны
ошибке маршрута: отдельно проверять TLS и chain. Проверить HTTP/80 и HTTPS/443.
T9: отказ **только KZ** смоделировать конфигом с портом 1 на 127.0.0.1 для
reality-kz; reload без рестарта XKeen, закрыть защищённые старые соединения.
Новые защищённые запросы должны падать, NL-запросы продолжать проходить;
AI.all остаётся единственным KZ. Затем восстановить валидный KZ и перепроверить.
T10: мутационное ревью тестов reviewer; финальный reviewer-final (fail-closed/платежи).
Проверки оплаты/загрузки документов требуют пользовательского браузера и не
подменяются GET главной страницы. Оплату/верификацию агент не выполняет.

## Порядок применения и откат

1. Reviewer спеки/контракта; тесты до правки шаблона, ожидаемый RED на старом конфиге.
2. Бэкап config.yaml, us-pool.list, cache.db, port_proxying.lst, снимки API
   proxies/rules/providers; локально `backups/20261030-kz-ai/`, права 0700/0600;
   копия на роутере `/opt/backups/20261030-kz-ai/`. Проверка хешей.
3. Изолированная проверка KZ. При неверной стране/неработоспособности — не мигрировать.
4. Подготовить шаблон, kz-pool и кандидат; тесты GREEN, `mihomo -t`.
   Reviewer-final до изменения активной конфигурации.
5. Загрузить KZ list, атомарно заменить config.yaml, PUT /configs с path,
   проверить API и закрыть старые защищённые соединения; T6/T8/T9.
6. Если KZ не работает после переключения — сохранить KZ-only отказ, сообщить
   владельцу. Автоматически возвращать AI на US/NL нельзя. Для аварийного
   восстановления NL подготовить конфиг с AI→REJECT (единственная опция),
   сохранив новые KZ-домены и приоритет; восстанавливать старый US-конфиг только
   с отдельного согласия владельца. SSH/интерфейсы/NDM не меняются.
7. Зафиксировать результаты, ограничения, новые решения в AGENTS.md/router.md,
   ADR о KZ-only. US-VM можно выключать только после подтверждения отсутствия
   активных зависимостей и успешных проверок.
