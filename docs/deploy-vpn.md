# Инструкция: внедрение VPN (XKeen 2.0 + Mihomo) на Keenetic Ultra

> Чек-лист внедрения и будущей автоматизации. Подробности/хроника: `AGENTS.md` («Решения»),
> `docs/specs/001-vpn-mihomo/review-log.md`, шаблоны: `mihomo/`, `xray/`.
> Принцип каждого шага: проверить → спросить владельца → применить → убедиться → только потом сохранять.

## 0. Предусловия (выполнено на 2026-09-19)

- [x] Entware на USB (aarch64), SSH по ключу, swap.
- [x] Шаблоны конфигов в репо + валидация (5 итераций, 2 APPROVE_WITH_NOTES).
- [x] Базовая линия роутера зафиксирована (чисто, ничего не установлено).
- [ ] От владельца: актуальная `vless://`-ссылка (server, uuid, sni, pbk, sid).

## 1. Бэкапы (перед ЛЮБЫМИ изменениями)

- [ ] `running-config` → `backups/` (CLI `more running-config` или веб).
- [ ] `tar` всего `/opt` (конфиги Entware с ключами в git не попадают).
- [ ] Зафиксировать baseline: версии OS/ядер, свободная RAM, `iptables` пуст.

## 2. KeeneticOS: компоненты (веб-интерфейс, не SSH)

- [ ] Установить компоненты: «Модули ядра Netfilter», «Прокси-сервер DNS-over-TLS»,
  «Прокси-сервер DNS-over-HTTPS». Перезагрузить, если попросит.
- [ ] Прописать шифрованный DNS. Замер домашней сети + хроника блокировок (авг-2026,
  ТСПУ режет :853 и SNI резолверов; см. ниже) дают выбор:
  - DoT основной: **AdGuard `94.140.14.14`** (резерв `94.140.15.15`) — указать **IP-адресом**:
    Keenetic шлёт SNI только при настройке по имени, IP выводит из-под SNI-фильтрации;
  - DoT резерв: **Quad9 `149.112.112.112`** (тоже IP-ом);
  - DoH (опция): `https://1.1.1.1/dns-query` — именно по IP в URL, без SNI cloudflare-dns.com.
  - НЕ использовать: Cloudflare DoT (заблокирован провайдером, замер 2026-09-20),
    Google DoT/DoH (обе волны августа били по Google+Cloudflare — вопрос времени),
    Яндекс (RU-резолвер), Mullvad/dns0.eu (недоступны).
  - Стратегическая страховка: даже если весь DoT/DoH отомрёт — схема не рушится:
    домены для роутинга определяет sniffer по SNI, резолв whitelisted-доменов делает
    VPS. Нативный DoT нужен только чтобы DNS не врали для прямого трафика.
- [ ] НЕ ставить «Сервер SSH» (конфликт с Entware dropbear).

### Приложение: замеры DNS и мобильный сценарий (2026-09-20)

- Домашняя сеть: работают AdGuard DoT (120 мс), Quad9 (117 мс), Google (582 мс),
  Яндекс (564 мс), OpenDNS, ControlD; DoH: Cloudflare/Google/Quad9/AdGuard/NextDNS/
  dns.sb/ControlD/Comss.one. Не работают: Cloudflare DoT (:853, таймаут),
  Яндекс DoH, dns0.eu, Mullvad.
- Хроника блокировок (Habr/zapret-wiki, авг-2026): ТСПУ режет порт 853 выборочно,
  DoH — по SNI резолверов (dns.google, cloudflare-dns.com, dns.adguard-*, dns.quad9.net
  были в списках разрывов, картина плавающая по операторам); с 26.08 открытый UDP/53 к
  1.1.1.1/8.8.8.8 DNAT-ится на резолверы НСДИ (заблокированные домены → NXDOMAIN).
  Вывод сообщества: долгосрочно устойчив только резолв внутри туннеля (у нас — VLESS).
- Тест через мобильный телефон (USB): на этой машине — WSL2, USB-тезеринг внутрь WSL
  не пробрасывается, adb не установлен. Инструкция на будущее: включить на телефоне
  «USB-модем», тестировать из Windows PowerShell (`curl.exe --interface ifIndex<N>`
  для DoH; `Test-NetConnection <host> -Port 853` для DoT), после теста галку выключить.
  Альтернатива: WSL mirrored networking + adb — только если появится необходимость.

## 3. Установка XKeen 2.0 (SSH → Entware)

- [ ] `opkg update && opkg upgrade && opkg install curl tar`
- [ ] Установщик форка JamesZero (install.sh с GitHub; при недоступности — зеркала/Offline).
- [ ] В установщике: ядра **Mihomo + Xray** (оба), гео Xray — опционально (запасное ядро),
  RU-IP-исключения — опционально, автообновление гео — по вкусу, **автозагрузка — да**.
- [ ] Убедиться, что режим по умолчанию Hybrid (443 веб-морды не трогаем).
- [ ] **Заполнить `/opt/etc/xkeen/port_proxying.lst`**: пустой файл = перехват ВСЕХ портов
  (причина фризов в играх при первом запуске 2026-09-20). Минимум: `80` и `443` —
  каждая на своей строке. Дисциплина: любое добавление портов (Discord/Steam-голос)
  = осознанное решение + тест игр.

## 4. Конфигурация (генерация из шаблонов → на роутер)

- [ ] Из `vless://`-ссылки извлечь: server, port, uuid, sni, publicKey, shortId, flow, fp.
- [ ] Заполнить плейсхолдеры в шаблонах: `<VPS_HOST> <UUID> <SNI> <PBK> <SID> <PANEL_SECRET>`
  (secret для панели — сгенерировать случайный).
- [ ] Реальные конфиги — ТОЛЬКО на роутере (`/opt/etc/mihomo/`, `/opt/etc/xray/configs/`).
  В репо — шаблоны; проверка утечки: `grep -n '<' <конфиги>` → пусто.
- [ ] Если GitHub с роутера недоступен — залить zashboard `dist.zip` вручную.

## 5. Preflight (ДО первого старта)

- [ ] Порты 5000/5001/9090 свободны (`netstat`; рядом Transmission на 9091).
- [ ] Доступность всех URL rule-providers с роутера (curl по списку из конфига) —
  mtest этого НЕ проверяет, а недоступный список = пустой whitelist.
- [ ] `xkeen -mtest` (синтаксис mihomo), `xkeen -xtest` (Xray).

## 6. Первый старт и приёмка

- [ ] `xkeen -start` → в выводе режим **Hybrid**.
- [ ] ПЕРВЫМ делом: метка/петля — `xkeen -pbr codes` vs `routing-mark: 255`,
  правила iptables на месте; убедиться, что исходящий трафик ядра не зациклился.
- [ ] Лог mihomo: НЕТ `initial rule provider ... error`; у каждого провайдера записи > 0.
- [ ] Тесты через прокси: instagram.com, youtube.com, telegram, chatgpt.
- [ ] Тесты напрямую (RU): 2ip.ru, сбербанк-онлайн, госуслуги — IP российский, без VPN.
- [ ] Игровой трафик: вне списков → напрямую (проверить на игре/steam).
- [ ] RAM под нагрузкой (стрим ютуба): тревога при > ~350 МБ из 512.
- [ ] IPv6 live-тест: ipv6-трафик к заблокированным доменам не должен обходить прокси;
  иначе — план Б `xkeen -ipv6` (эксперимент).
- [ ] Watchdog-тест: `kill -9` mihomo → кто поднимает и через сколько; правила живут?
  Если никто — решить мини-cron `xkeen -restart`.
- [ ] WAN-сторона: 9090/5000/5001 закрыты снаружи (проверить с мобильного интернета).
- [ ] Панель: `http://192.168.1.1:9090/ui` с secret; группы переключаются.

## 7. Автозагрузка и контрольная перезагрузка (согласовать окно 2–4 мин!)

- [ ] Владелец предупреждён: дом без интернета 2–4 минуты.
- [ ] Reboot → после подъёма: интернет DIRECT работает до старта Entware (fail-open),
  XKeen поднялся сам, правила перехвата на месте, панель доступна, прокси-тесты ок.

## 8. Финал

- [ ] Владелец: «Сохранить» в вебе (⇔ `system configuration save`).
- [ ] Записать в `docs/router.md`: версии ядер, дату, фактические порты/теги inbound.

## Откат

- Мягкий: `xkeen -stop` → вернуть бэкап конфигов → перезапуск.
- Полный: `xkeen -remove` (+ при нужде восстановление `/opt` из tar).
- Последняя инстанция: **перезагрузка роутера** (iptables-правила неперсистентны).

## Будущая автоматизация (целевой вид, НЕ реализовано)

Скрипт из корня репо (например `scripts/deploy-vpn.sh`), стадии = этапы этой инструкции:

1. preflight: доступность роутера по SSH, baseline, бэкапы → `backups/<дата>/`.
2. render: интерактивно/из env принимает `vless://` + генерирует секрет панели →
  рендерит конфиги из шаблонов во временную папку (секреты не в git!).
3. deploy: scp конфигов на роутер, установка XKeen (идемпотентно, если уже стоит).
4. verify: порты, curl провайдеров, mtest/xtest.
5. start + acceptance: старт, лог-критерии, proxy/RU-тесты, RAM → отчёт PASS/FAIL.
6. НЕ автоматизируется: перезагрузка и `system configuration save` — только владельцем
  (подтверждение интерактивно); вывод vless-ссылки — интерактивно, не из файлов.
