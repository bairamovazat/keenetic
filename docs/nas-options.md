# Варианты собственного файлового хранилища (NAS) в локальной сети

> Контекст: тариф 900 Мбит/с; сценарии — торренты, медиатека для устройств по Wi-Fi,
> своё приложение с позициями просмотра. Вариант «диск на роутере» (~100 МБ/с, CPU-bound)
> признан недостаточным. Скорость интернета — 112 МБ/с; локальные переливы хотят больше.

## Потолки скорости в текущей сети

| Звено | Скорость |
|---|---|
| 1GbE (кабель, стандартные LAN-порты роутера) | ~112 МБ/с |
| Wi-Fi 6 5 ГГц (рядом с точкой) | 75–150 МБ/с |
| 2.5GbE (порт 2.5GE роутера + 2.5G-адаптеры) | ~280 МБ/с |
| NVMe напрямую | GB/s — по сети недостижимо, забудем |

Важно: порт 2.5GE у KN-1811 сейчас WAN, любой порт можно перенастроить в LAN (CLI/веб).

## Вариант A: отдельный бокс-NAS (правильный путь для «максимума»)

- Железо: б/у мини-ПК (Intel N100/N305 — тихие, 6–15 Вт, дешёвые на вторичке)
  или старый неттоп/ноутбук; SSD кандидата (NVMe со старой Windows) — внутрь, без USB-боксов.
- ОС: **OpenMediaVault** (Debian с веб-мордой: SMB/NFS/торренты/Docker из коробки)
  или чистый Debian + Docker (больше контроля).
- Сеть: встроенный 2.5GbE у N100-боксов — сразу ~280 МБ/с к роутеру (порт 2.5GE → LAN).
- Стек «плюшек» (Docker): qBittorrent + *arr (Sonarr/Radarr/Prowlarr) + Jellyfin
  (аппаратный транскодинг Intel QSV — даже 4K тянет) + Samba/NFS.
- Своё приложение — рядом в Docker, SQLite на том же SSD, без ограничений роутера.
- Цена владения: ~7–15 Вт 24/7 ≈ 400–800 ₽/год электричества.

## Вариант B: существующий игровой ПК как сервер

- Ноль затрат на железо: Windows SMB-шары + qBittorrent + Jellyfin на Windows.
- Минусы: ПК должен быть включён 24/7 (50–100 Вт простоя ≈ 3000–6000 ₽/год),
  шум, обновления Windows перезагружают «сервер».
- Полусон: Wake-on-LAN из роутера — качалки всё равно требуют постоянной работы.
- Годится как временный этап «попробовать сценарии», не как конечное решение.

## Вариант C: готовый NAS (Synology/QNAP)

- Дорого за 2.5G, экосистема закрытая, Docker урезан. Для энтузиаста — худший вариант.

## Вариант D: диск на роутере (отложен, не отменён)

- ~100 МБ/с, лёгкие сервисы Entware. Остаётся как лёгкий узел: Entware-флешка в любом
  случае ставится под XKeen. Хранилище медиатеки — уже нет.

## Рекомендация

1. Краткосрочно: поднять сценарии на своём ПК (вариант B) — проверить торренты/Jellyfin/своё приложение.
2. Целевое: N100-бокс + OpenMediaVault/Docker (вариант A), SSD-кандидат внутрь,
   2.5G-порт роутера → LAN. Тогда «диск на роутере» остаётся только под Entware/XKeen.
3. Роутер из схемы медиатеки уходит полностью — не мешает ни скорости, ни CPU.

## Примечания

- SSD со старой Windows: образ системы (DiskGenius) → файл на новый диск, разделы под IEEE.
- Транскодинг на KN-1811 невозможен (CPU), поэтому медиасервер — только на A/B.
- Скорость ПК↔NAS ограничена самым медленным звеном: у ПК 1GbE? → 112 МБ/с, чтобы
  получить 2.5G — адаптер в оба конца.
